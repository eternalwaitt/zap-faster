## Maintenance loop

1. Fetch upstream main and list open PRs/issues. Keep upstream as a read-only remote.
2. Record the source URL, head revision, author, decision and dependencies here. Reproduce reported issues with synthetic data.
3. Review account isolation, archive/keyring compatibility, protocol support and privacy. Adapt code to current architecture; never import stale state wholesale.
4. Keep focused linear commits with `Upstream-PR` and `Upstream-Head` trailers and original author credit. Run the required checks before release.
5. Mark integrated PRs here, revisit deferred work when dependencies are ready, and record issues fixed locally with source links. No upstream comments are sent automatically.
